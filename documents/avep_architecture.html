Autonomous Video
Editing Pipeline

A 4-layer agentic system that separates content intelligence from media processing — turning raw footage into a validated rough cut while preserving the original source file.

LAYER 01
👁
Perception
Sensory Input
Converts raw video/audio into structured data. Runs Faster-Whisper, Silero VAD, and optional DeepFilterNet locally. NVIDIA uses CUDA; Apple Silicon transcription uses CPU.
→
LAYER 02
🧠
Decision Agent
The Brain
Provider-scoped LLM calls or local heuristics produce a schema-validated JSON edit plan with bounded, non-overlapping timestamps.
→
LAYER 03
🔗
Metadata Bridge
The Glue
Exports media-linked FCPXML, EDL, and OTIO timelines from the edit plan for review or continued work in an NLE.
→
LAYER 04
💪
Execution
The Muscles
FFmpeg reads the validated edit plan and renders with VideoToolbox or NVENC when usable, automatically retries with libx264 when needed, then verifies the output with ffprobe.

Why This Architecture Wins

🛡
Non-Destructive
The original footage is never altered. Timeline exports reference it, while FFmpeg writes a separate rendered output.
🎛
Multimodal
The agent simultaneously "hears" silence via VAD and "reads" intent via the transcript — combining acoustic and semantic signals.
⚡
GPU-Efficient
The renderer detects supported hardware encoders and falls back to libx264. Performance depends on device, model size, and source duration.

How AVEP Works
🤖✂️🎬

Imagine a robot that watches your video, decides what to keep, and hands a perfect edit to a professional video machine — all automatically.

🎙️
Layer 1 · Perception
The Robot Listens 👂
Your video goes in. Whisper produces a word-level transcript, while Silero VAD maps speech and silence. Optional noise reduction can improve difficult audio before transcription.
🧠 Like a friend writing down everything you said while watching your video
🤔
Layer 2 · Decision Agent
The Brain Decides 🧠
A selected cloud or local model reads the transcript and proposes what to keep and remove. AVEP validates every timestamp before the plan can reach the timeline exporter or renderer.
✂️ Like a film director marking a script with a red pen
📋
Layer 3 · Metadata Bridge
The Instructions 📝
AVEP writes media-linked FCPXML, EDL, and OTIO recipe files for professional editors. These reference the original footage rather than modifying it.
🗺️ Like GPS directions for a video editor — never touching the road, just giving instructions
🎬
Layer 4 · Execution
The Powerful Machine Renders 💪
FFmpeg applies the validated cuts, selects an available hardware encoder when possible, writes a separate MP4, and checks that the result is a valid video. The exported timeline can also be opened manually in an NLE.
🏭 Like a factory that follows the blueprint to build the final product at full speed
🎉

The Magic Result

You drop in a raw recording. AVEP transcribes, analyzes, validates, exports timelines, and produces a separate rough-cut MP4 while leaving the original source untouched.

Developer Reference · Technical Spec

Architecture Deep Dive

Complete technical breakdown of each layer, data contracts, toolchain specs, and integration points for engineers building or extending AVEP.

L1

Perception Layer

Entry Point
Input: Raw .mp4 / .mov / .wav
Output: JSON transcript with word-level timestamps + VAD silence map
Transcription Engine
# faster-whisper setup from faster_whisper import WhisperModel model = WhisperModel( "large-v3", device="cuda", # CPU on Apple; CTranslate2 has no MPS backend compute_type="float16" # int8 on CPU ) segments, info = model.transcribe( audio_path, word_timestamps=True, vad_filter=True )
VAD / Silence Detection
# silero-vad for silence map import torch vad_model, utils = torch.hub.load( repo_or_dir='snakers4/silero-vad', model='silero_vad' ) # Returns list of (start_ms, end_ms) speech segments
Noise Reduction
Tool: DeepFilterNet v2 (local Python model)
Run before transcription for cleaner word boundaries
Outputs cleaned .wav; original audio is preserved
L2

Decision Agent

Agent System Prompt Pattern
SYSTEM = """ You are a professional video editor AI. Given a timestamped transcript, output a JSON 'edit_plan' with these fields: - keep_segments: [{start, end, reason}] - remove_segments: [{start, end, reason}] - flag_zoom: [{start, end}] Return ONLY valid JSON. No prose. """
Edit Plan Output Schema
{ "keep_segments": [ { "start": 0.0, "end": 12.4, "reason": "clean take" } ], "remove_segments": [ { "start": 12.4, "end": 14.1, "reason": "filler: um" } ], "flag_zoom": [ { "start": 45.2, "end": 48.0 } ] }
Decision Modes
Heuristic mode: removes silence >0.8s and single-word fillers without an LLM
LLM mode: transcript correction followed by provider-scoped edit planning
Validation: finite, bounded, ordered, non-overlapping edit segments
Planned: deterministic repeated-take detection and applied zoom effects
L3

Metadata Bridge

OpenTimelineIO (OTIO)
import opentimelineio as otio timeline = otio.Timeline(name="AVEP_Edit") track = otio.Track(name="V1") for seg in edit_plan["keep_segments"]: clip = otio.Clip( source_range=otio.TimeRange( start_time=otio.RationalTime( seg["start"] * fps, fps), duration=otio.RationalTime( (seg["end"] - seg["start"]) * fps, fps) ) ) track.append(clip) # Export FCPXML for DaVinci / Resolve otio.adapters.write_to_file( timeline, "output.fcpxml" )
Supported Export Formats
FCPXML — DaVinci Resolve, Final Cut Pro
EDL (CMX 3600) — Universal NLE compatibility
OTIO JSON — Internal interchange, version control
L4

Execution Layer

Implemented Render Path
# validated edit_plan.json → FFmpeg select/aselect plan = validate_edit_plan(plan, duration=media_duration) video_filter = "select='between(t,start,end)+...',setpts=N/FRAME_RATE/TB" audio_filter = "aselect='between(t,start,end)+...',asetpts=N/SR/TB" # Render to a temporary MP4, verify with ffprobe, then atomically publish
FFmpeg Fallback (No Resolve)
# Mac: VideoToolbox hardware encode ffmpeg -i input.mp4 \ -vf "select='...'" \ -c:v h264_videotoolbox \ -b:v 8000k output.mp4 # NVIDIA: NVENC hardware encode ffmpeg -i input.mp4 \ -c:v h264_nvenc \ -preset p7 -b:v 8000k output.mp4
Reliability Guarantees
Invalid or empty edit plans fail before rendering
Advertised hardware encoders automatically fall back to libx264 if startup fails
Partial output is never published as the final result
Final output must pass ffprobe validation

Engineering Roadmap · Current Status

Hardening and Next Features

The core pipeline is implemented. These original layer assignments now serve as a roadmap: reliability work is active, while deterministic duplicate detection, applied zoom effects, persistent jobs, and optional Resolve automation remain planned.

TASK-01 Layer 1
Harden the Perception Layer
Implemented · Needs E2E Tests
What to Build
  • Python script that accepts a video file path as CLI argument
  • Runs Faster-Whisper with word-level timestamps
  • Runs Silero-VAD to detect silence regions
  • Optionally runs DeepFilterNet for audio cleaning
  • Outputs a single perception_output.json
Prerequisites / Setup
  • pip install faster-whisper silero-vad torch
  • CUDA for NVIDIA; CPU fallback on Apple Silicon and other systems
  • ffmpeg installed on system PATH
  • A sample raw video file for testing (~5 min)
Success Criteria
  • Output JSON contains word-level timestamps accurate to ±0.1s
  • Silence regions > 0.5s are all captured in the map
  • Script completes in under 5 min for a 1-hour video on GPU
  • Works without GPU (slower) as a fallback
Deliverable → perception.py + perception_output.json schema + README.md
TASK-02 Layer 2
Expand the Decision Agent
Implemented · Creative Logic Planned
What to Build
  • Python agent that reads perception_output.json
  • Pre-processing heuristics: silence removal, filler word regex
  • Repeated take detection using sentence similarity
  • LLM call (Gemini/GPT-4o) for intent analysis
  • Outputs edit_plan.json (keep/remove/zoom segments)
Prerequisites / Setup
  • OpenAI or Google Gemini API key in .env
  • pip install openai google-genai python-dotenv
  • perception_output.json from Task-01
  • Review the JSON schema before coding the prompt
Success Criteria
  • All filler words ("um", "uh", "like") are flagged for removal
  • Duplicate takes: only the last repetition is kept
  • Output JSON validates against the agreed schema
  • Agent runs for <60 tokens cost per minute of video
Deliverable → agent.py + edit_plan.json sample + prompt_template.txt
TASK-03 Layer 3
Validate NLE Interoperability
Media-Linked Export Implemented
What to Build
  • Python script reading edit_plan.json
  • Generate OTIO timeline object from keep segments
  • Export .fcpxml for Resolve and .edl for NLE fallback
  • Frame-accurate timing using source video's FPS metadata
Prerequisites / Setup
  • pip install opentimelineio
  • Read OTIO docs for FCPXML adapter
  • Understand the source video FPS (24, 30, 60)
  • DaVinci Resolve installed for validation
Success Criteria
  • FCPXML imports into DaVinci Resolve without errors
  • Timeline matches expected cut points from edit_plan.json
  • Zero quality loss — original source media referenced only
  • EDL file imports into at least one other NLE (Premiere)
Deliverable → bridge.py + output.fcpxml sample + output.edl sample
TASK-04 Layer 4
Advance Rendering and NLE Automation
FFmpeg Implemented · Resolve Planned
What to Build
  • Python script using DaVinci Resolve's scripting API
  • Auto-import the FCPXML timeline from Task-03
  • Apply a color grade LUT (optional but ideal)
  • Set render codec to H264 with hardware acceleration
  • Trigger render and monitor completion
Prerequisites / Setup
  • DaVinci Resolve Studio (not free version)
  • Enable "External Scripting" in Resolve preferences
  • Python path configured to use Resolve's bundled Python
  • FCPXML from Task-03 ready to import
Success Criteria
  • Script runs end-to-end without manual UI interaction
  • Final MP4 output is generated at target bitrate
  • Hardware encoder (videotoolbox / nvenc) is confirmed active
  • FFmpeg fallback script also provided for non-Resolve users
Deliverable → render.py (Resolve) + render_ffmpeg.py (fallback) + final_cut.mp4
